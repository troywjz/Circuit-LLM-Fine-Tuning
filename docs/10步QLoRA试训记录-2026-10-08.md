`adapter_model.safetensors` 通过 `safetensors.safe_open` 只读取张量键、形状与 dtype 元数据，没有读取原始基座权重张量。文件中共 256 个张量，均含 `lora_A` 或 `lora_B`，两类都有；LoRA rank 维度为 8；全部张量 dtype 为 `F32`。10,616,832 个 FP32 参数按每个 4 字节计算约为 42,467,328 B；文件总长 42,500,760 B，另含文件头和键元数据。因此训练计算使用 BF16 不等于 adapter 保存为 BF16。主 Agent 另行逐张量检查：256 个张量数值全部有限，128 个 `lora_B` 张量全部非零，adapter 配置为 `init_lora_weights=true`、rank 8。详见[适配器文件与键形状清单](../experiments/reports/2026-10-08-10步QLoRA/适配器核验.json)及[主 Agent 数值复核](../experiments/reports/2026-10-08-10步QLoRA/主Agent复核.json)。原始两片基座权重的 SHA256 前后完全一致，详见[原始权重校验记录](../experiments/reports/2026-10-08-10步QLoRA/原始权重校验.json)。

## 问题、修复与限制

- 本次没有阻塞错误，因此没有修改依赖、切换路线或重跑失败阶段。
- 原始权重 SHA256 初次采集命令的 PowerShell 管道写法解析失败，改为先收集数组再序列化后成功。失败发生在模型操作前，不影响推理或训练；后续前后 SHA256 一致。详情见[权重校验记录](../experiments/reports/2026-10-08-10步QLoRA/原始权重校验.json)。
- 启动时 Transformers 对 `torch.compile` 枚举注册给出弃用警告；生成时 `causal_conv1d` 未安装，日志提示使用参考 PyTorch 实现。这是正确性路径可用但速度较慢的提示，不是运行错误；按要求未安装任何依赖。
- 训练日志报告 tokenizer 的 PAD/BOS/EOS 与模型配置有差异；训练加载阶段在内存中将模型配置与 generation config 自动对齐。脚本只把 adapter 和 tokenizer 保存到本次 adapter 目录，没有把基座配置或权重写回原始模型目录。
- 训练器报告可训练参数 10,616,832，占总参数约 0.25%。8 条玩具样本经过 5 个 epoch 并重复使用；训练目标是完整对话文本，没有设置只对 assistant 回复计算损失的 mask。因此不能把下降中的训练 loss 当成外部泛化证据。
- **HYPOTHESIS（未验证）：** 这次参数和小样本可能会让输出风格更贴近玩具样本；需要冻结、独立、按项目切分的 Benchmark 才能评估实际效果。
- 该运行仅覆盖文本推理与小步数训练；不验证多模态、长上下文能力、正式数据质量、电路正确性、物理板卡或生产能力。
