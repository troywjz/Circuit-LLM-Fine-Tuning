# 数据整理程序

`scripts/prepare_dataset.py` 根据用户提供的资料生成待审候选；程序不核验许可、器件事实或物理结果。真实服务连通性已验证，但尚无真实 QA 生成质量结论；首轮建议以真实工程问答为主，少量加入代码连接摘要，先试跑 3 条并人工检查，再扩大批次。

当前数据路线与规模是计划：主数据取 [Electrical Engineering Stack Exchange](https://electronics.stackexchange.com/) 电源、散热、接口等真实工程问答；辅助数据取 [microsoft/SchGen_dataset](https://huggingface.co/datasets/microsoft/SchGen_dataset)，只抽取给定代码中的连接关系用于解释，不直接训练生成 KiCad 代码。数据卡标注 MIT 仅是元数据，不代表每条内容已核验或自动获得授权。[Stack Exchange 授权说明](https://electronics.stackexchange.com/help/licensing)：每条帖子须保留作者、原帖链接和该帖适用的 CC BY-SA 版本。先按项目家族和近似副本分组，再让 Teacher 改写；test 资料不参与 train 生成。计划规模：120 train（100 领域、20 通用/多轮）、20 validation、50 test（40 领域、10 通用）；这些是目标数，不是已完成数据量。

## 配置与试跑

将根目录 `.env.example` 复制为本机 `.env`，填写四项：`TEACHER_PROVIDER`、`TEACHER_BASE_URL`、`TEACHER_API_KEY`、`TEACHER_MODEL_ID`。模型名称不决定接口协议；已验证兼容网关可通过 OpenAI Responses 返回声明为 Claude 的响应。模型 ID 和协议均按服务方实际支持的配置填写。

本轮新采集的原始资料保存在私有目录，`split` 为 `null`、审核状态为 `pending`、`training_eligible` 为 `false`。按项目家族和近似副本分组、审核后，再转换成程序所需输入；原始采集格式不能直接作为训练对话使用。

中文路线保留原文、来源和许可，先划分集合，再用原文生成中文任务对话，不先翻译整库。主 Agent 先核对 3–5 条中文题干和术语，批量改写使用获准承担该用途的 API。当前程序要求 `student_context` 原样出现在 user 消息中，所以须先准备可追溯、已核对的中文题干。题干不得加入参考答案或评分要点；翻译核对也不等于工程事实核验。

训练 `messages` 的自然语言使用中文，型号、代码和必要英文术语原样保留。英文原文及审核元数据单独保存，不把整篇参考答案拼入学生题干；服务用途授权见下文。

默认输入为 `本地资料/数据准备/原始资料输入.jsonl`，默认输出为 `本地资料/数据准备/候选输出/`。`examples/资料样例.jsonl` 是 3 条自编格式示例，split 分属 train、validation、test；它不是项目真实数据，也不能替代真实输入。

```powershell
python scripts/prepare_dataset.py --dry-run
python scripts/prepare_dataset.py --export-prompts
python scripts/prepare_dataset.py --limit 3
```

首条只检查输入并展示任务数，不会调用模型或生成候选；第二条导出私有任务包供人工送入 Teacher；第三条通过配置调用 Teacher。`--check-config` 单独运行可查看缺少哪些必填字段，不显示配置值。`--input`、`--output-dir`、`--env-file` 可覆盖默认路径。

## 输入与审核

输入是 UTF-8 JSONL，每行一个 JSON 对象，至少包含 `source_id`、`project_id`、`group_id`、`split`、`task`、`student_context`、`sources`。split 为 `train`、`validation`、`test`；任务类型为 `澄清需求`、`给出方案与取舍`、`多轮需求修订`、`已有设计解释`、`错误识别`。`sources` 是对象列表，每项需有唯一的 `source_id`、非空 `content`、`url` 和 `license`。同一项目、家族或来源不得跨 split；超长输入会拒绝，不静默截断。

每条 Teacher 输出需含 `task`、`messages`、`evidence`、`expected_points`、`hard_errors`。`evidence` 引用输入已有来源 ID，并标注 `SOURCE_FACT`、`DERIVED`、`HYPOTHESIS` 或 `UNCONFIRMED`。`train`/`validation` 候选保留 `messages`；`test` 候选将最后一条 assistant 答案单独存入 `reference_answer`，可见输入只放在 `input_messages`。所有候选初始均为“待审”，`training_eligible` 为 false；格式校验通过不等于样本获准训练。

人工生成时，把任务包中的原始文本保存为同名 `<job_id>.json`，内容格式为 `{"text":"教师返回的原始文本"}`，然后运行：

```powershell
python scripts/prepare_dataset.py --response-dir "本地资料/数据准备/教师返回" --output-dir "本地资料/数据准备/候选输出"
```

离线回填会走同一格式和来源引用校验，不调用 API。需要续跑时加 `--resume`：匹配的成功任务会跳过；扩大到前 6 条可用 `--limit 6 --resume`。已有结果损坏或输入任务与历史样本冲突时拒绝继续；修改资料、模型或整理配置后应使用新输出目录。手工路线先确定配置再导出任务包，回填时保持配置一致。

可用 `--tokenizer-path` 指向本地 tokenizer，并用 `--max-sample-tokens` 设置完整对话长度上限（默认 2048）；未提供 tokenizer 时不估算 token 数。这里限制的是本轮训练样本长度，不是部署时的上下文窗口。
