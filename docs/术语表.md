# 术语表

本表只收项目里会反复出现的词，第一次出现在其他文档时引用这里即可。

## 模型与训练

| 术语 | 一句话解释 |
|---|---|
| 参数（Parameter） | 模型里可被训练调整的数字，数量决定模型大小（4B = 40 亿个） |
| Base 模型 | 只做过预训练、没学过"怎么回答问题"的模型，适合拿来做微调的起点 |
| Instruct / Instruct 模型 | 已经教过怎么对话的模型，开箱可用 |
| 微调（Fine-tuning） | 用你自己的数据继续训练模型，让它学会特定领域的习惯 |
| SFT | 监督式微调——给模型看"问题 + 标准答案"的配对数据，是最常用的微调方式 |
| LoRA | 冻结原模型，只在旁边挂一小块可训练的参数（适配器），大幅省显存 |
| QLoRA | LoRA 的省显存版，先把原模型压成 4 位精度再挂适配器 |
| 适配器（Adapter） | LoRA 训练产生的"补丁文件"，几十 MB，可与基座模型合并 |
| epoch | 把全部训练数据完整学一遍叫 1 个 epoch。学太多遍会"背答案" |
| 学习率（Learning Rate） | 每次调整参数的幅度，太大训不稳，太小训不动 |
| 灾难性遗忘 | 只学新领域后，把原来的通用能力弄丢了 |
| 量化（Quantization） | 用更少的位数存参数，模型变小、变快，精度略降 |
| 4-bit / 8-bit | 每个参数用 4 位 / 8 位存，4-bit 大约是原始体积的 1/4 |
| 显存（VRAM） | 显卡自带的内存，模型和训练中间结果都放这里，装不下就报 OOM |
| 推理（Inference） | 用训练好的模型回答问题，只读不算梯度，显存需求远低于训练 |
| 代币（Token） | 模型读写文字的最小单位，约等于一个词或半个汉字 |
| 上下文长度（Context） | 模型一次能"看到"多少 token，超出要截断 |
| Teacher 模型 | 用来生成参考答案的强模型（本项目里是尖端大模型），学生模型向它学 |
| 蒸馏（Distillation） | 用 Teacher 产出的数据训练小模型，把大模型的能力搬过来 |
| Benchmark | 标准化考卷，用来客观比较不同模型的表现 |
| 基线（Baseline） | 微调前的原始模型成绩，用来证明微调到底有没有用 |

## 文件与格式

| 术语 | 一句话解释 |
|---|---|
| safetensors | HuggingFace 主流的权重存储格式，加载快、比老的 `.bin` 更安全 |
| GGUF | llama.cpp 生态的单文件格式，专为推理设计，支持各种压缩等级（如 Q4_K_M） |
| AWQ / GPTQ | 面向推理的 4 位量化格式，需要特定推理引擎支持 |
| FP8 / Int4 | 8 位浮点 / 4 位整数的精度表示，数字越小越省内存、精度越低 |
| MLX | 苹果芯片专用的模型格式，与 NVIDIA 无关 |

## 项目内概念

| 术语 | 一句话解释 |
|---|---|
| Circuit IR | 从 EDA 工程文件解析出来的结构化中间数据（器件、引脚、网络等） |
| Master Record | 单个项目的"事实 + 推断"中间层，是生成各种训练样本的源头 |
| Design Intent | 设计意图——本项目的模型输出物，即"为什么这么设计"的说明 |
| Schema | 数据格式约定，规定一份数据有哪些字段、字段什么含义 |
| 证据分级 | 区分 SOURCE_FACT（原始资料直接证明）/ DERIVED（可靠规则推导）/ HYPOTHESIS（合理猜测）/ UNCONFIRMED（资料不足） |
