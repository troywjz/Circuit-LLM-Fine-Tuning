# 正式实验数据准备

正式实验围绕电路需求分析和对话能力组织数据。上一轮的少量样本用于检查训练与评测流程；新一轮使用单独的来源划分和评测题，结果完成后再报告。

## 数据怎么准备

1. 收集公开的电路问答、工程项目和通用中文对话，记录原文、来源版本、作者和许可信息。原始资料与生成结果放在 Git 忽略的本地目录。
2. 按原题、项目和派生关系分组，再安排训练、开发和最终测试候选。旧实验的最终题及其关联来源继续隔离。`scripts/formal_split_sources.py --help` 查看问答来源划分入口；不同数据集先适配各自的分组信息。
3. 选取适合当前任务且可使用的训练来源，交给教师模型整理成中文对话。任务可包括需求澄清、方案比较、已有设计解释、错误识别和多轮修订。样本保留来源与审核记录；训练只读取对话内容。
4. 检查生成内容、工程事实和使用条件，审核通过后才纳入训练。长样本要保留关键条件；超过训练窗口时拆分或退回修改。
5. 在训练前冻结新的开发题和最终题。最终题不参与训练和调参；Base 与微调模型使用一致的本地推理设置。强参考模型独立答题，使用同一题目和自身对话历史。

工程资料可能包含图纸或代码，能否直接使用取决于输入方式、许可和任务范围。当前 V0 聚焦从需求到 Circuit Design Intent，自动原理图与 PCB 生成不属于本轮目标。

## 按账户余额生成

`scripts/build_demo_data.py generate` 的 `--use-account-balance` 使用账户实时余额，不沿用旧 Demo 的项目预算和保留额。来源包和主 Agent 的生成许可清单要先准备好；`--dry-run` 只列出计划处理的来源数量，不调用模型，正式运行时还会检查来源分组和账本。详细参数可运行：

```powershell
python scripts/build_demo_data.py generate --help
```

余额模式使用独立的本地输出目录和账本，记录本批总数、已生成、已审核、待生成和待审核数量。每次请求前检查余额，单次请求不自动重试；网络中断等结果不明的情况会停下，核对后再处理。`--resume` 可复用已保存的完整回复，并校验来源和配置，避免重复生成。原始回复与经过审核的候选分别保存。

整理通用中文对话时可配合 `--general-dialogue`，使用适合日常交流、写作和编程的提示；工程来源默认使用电路对话提示。两种任务各用独立批次，已有批次续跑时保持原有选项。

`scripts/demo_api_reference.py --use-account-balance` 可按相同余额规则生成强参考答案，默认读取环境配置的模型名称。题目输入只给学生可见消息；多轮对话使用强参考自己生成的历史。程序逐轮保存回复和进度，未决请求不会自动重发。参考运行与教师数据生成共用本地锁，避免同时请求。

连接测试命令为 `python scripts/test_teacher_connection.py --env-file .env`；备用配置先尝试 Anthropic，若服务明确拒绝该协议，再试 `TEACHER_BACKUP_OPENAI_API` 指定的 OpenAI 兼容方式。数据准备按 `.env` 的 `TEACHER_PROFILE_ORDER_DATA` 顺序调用 API，默认 `backup,primary`；可用 `--teacher-profile` 只选一个。遇到 HTTP 400、401、404、413、422，或明确限流的 429 时，会转到下一项；额度/账单错误、403、超时、5xx 和结果不明会停止，避免重复计费。强参考评测固定只用旧的 `primary`，且 `TEACHER_PROFILE_ORDER_REFERENCE` 必须设为 `primary`。若网关的 `/usage` 明确返回 404、405 或 501，且项目已获准依靠服务端额度错误停止，可对数据生成加 `--allow-unknown-balance`。备用参数只放在被 Git 忽略的本机 `.env`。

程序检查格式和长度，不能代替来源许可审查及工程内容审核。公开代码的 MIT 许可不自动覆盖第三方数据、模型权重或教师输出。
