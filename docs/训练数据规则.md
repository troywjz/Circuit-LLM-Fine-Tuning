# 训练数据规则

训练目标是简短、自然的电路规划对话，包括需求澄清、方案比较、冲突识别、需求修订和已有设计解释；同时保留通用多轮对话能力。模型学习分析和沟通方式，器件参数与引脚事实须来自用户可见资料或约定的检索结果。

每个候选样本记录来源、版本或采集信息、使用范围、项目/家族分组、任务类型、消息内容和审核状态。重要工程断言标注 `SOURCE_FACT`、`DERIVED`、`HYPOTHESIS` 或 `UNCONFIRMED` 并保留可定位依据。格式转换或模型生成不等于事实核验；合成和改写内容也要审核。权利或关键资料未确认的样本不得进入训练。模型和数据各自遵循其原授权；原始数据与权重不纳入源码仓库。

最小记录字段为 `sample_id`、`project_id`、`group_id`、`task`、`messages`、`sources`、`evidence`、`review`、`split`。普通对话训练只读取 `messages`，审核与来源元数据不拼入模型输入；答案所需资料须另放在学生可见的消息中。

按项目家族、近似副本和派生关系分组后，再划分 train、validation、test，避免同一设计跨集合泄漏。测试题和参考要点不用于生成训练数据或调参；测试集在正式训练前冻结。仅审核通过的样本进入训练，错误设计可用于错误识别任务，但目标回答必须指出问题。

正式 SFT 前，用真实样本核对 tokenizer/chat template、EOS、单轮与多轮 assistant 监督范围及样本长度。不得静默截断关键约束；超长样本应拆分为保留上下文的子任务或退回修改。短 smoke 使用的玩具样本不属于正式数据。
