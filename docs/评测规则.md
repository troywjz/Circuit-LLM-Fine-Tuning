# 评测规则

正式训练前冻结一组小型领域题和通用多轮题、参考要点与评分版本，并保证评测项目与训练数据隔离。覆盖需求澄清、正向规划、器件权衡、错误/冲突识别、需求修订和已有设计解释。题目应说明模型可用资料、关键要求和明确错误，允许多个合理方案。小型试点评测用于发现问题，不代表稳定能力或安全保证。

按题目预先选定的维度进行人工评分：任务与约束、工程/事实正确性、不确定性与证据、理由及多轮一致性、清晰度。每个适用维度按 0–2 分；评测前确定适用项和通过门槛。明确危险或不兼容的连接建议、编造关键器件事实、违反关键约束属于硬错误，应单独计数并使对应题不通过。

单题暂行合格线为适用项得分归一化后不低于80、各适用项至少1分且无硬错误；不适用项不计入分母，并在看回答前确定。这个筛查线不替代微调收益或生产力验收门槛，后两项须在基线后、正式训练前冻结。

在相同基座、量化、提示、资料、工具权限、模板和生成设置下比较 Base 与 FT；如配置不同，分别报告，不能把差异归因于微调。测试集只用于阶段验收；根据测试结果修改题目、提示或标准时，应记录污染并建立新版本。记录模型/adapter 标识、数据和评分版本、生成参数、回答、逐题评分与失败原因。

分别报告领域任务得分和硬错误、通用多轮回归、延迟与资源使用，并按合格任务核算成本。数据外发行为单独核验；本地权重或一次成功推理不证明隐私隔离。评测结果不能代替器件核验、物理验证或产品验收。
